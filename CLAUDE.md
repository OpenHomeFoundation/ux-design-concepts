# UX design concepts — project notes

## Repo structure
- Only `public/` is deployed. Each design concept lives in its own folder inside it, with an `index.html` entry point (e.g. `public/device-database/`). Repo tooling (package.json, build.js, README, this file) stays outside `public/` and is never served.
- `public/index.html` is generated by `pnpm build` (runs `node build.js`). It scans `public/` folders for an `index.html`, uses each page's `<title>` as the concept name and an optional `<meta name="description">` as the blurb, and renders an index styled after openhomefoundation.org. Do not edit `public/index.html` by hand.
- Deployed on Cloudflare as a static-assets Worker named `ux-design-concepts`. Config lives in `wrangler.jsonc` at the repo root (`name`, `build.command: pnpm build`, `assets.directory: ./public`). `wrangler deploy` runs the build command first, so every deploy (including push-triggered Workers Builds) regenerates `public/index.html` before serving `public/`. The build command must stay `pnpm build` (not `node build.js`): Workers Builds runs the deploy command from the `public/` root directory, and pnpm resolves the root `package.json` from any subdirectory while a bare `node build.js` fails there. The `name` in `wrangler.jsonc` must stay `ux-design-concepts` so deploys update the existing Worker instead of stopping.
- Search engines are blocked everywhere: `robots.txt` (Disallow all), `_headers` (`X-Robots-Tag: noindex, nofollow` on every path), plus `noindex` meta tags on entry pages. Keep it that way for new concepts.

## Writing / copy style
- **Never use em dashes (—) in any user-facing copy or content.** Do not use them in prose, labels, titles, descriptions, or UI strings. Rephrase with commas, periods, parentheses, or a colon instead. This applies to all future edits.
- Empty-value placeholders use a plain hyphen ("-"), not an em dash.
- En dashes (–) for numeric ranges (e.g. "2200–6500 K") are fine.
- **Never use the "&" ampersand in user-facing copy. Write the word "and" instead** (e.g. "Ecosystems and apps", not "Ecosystems & apps"). This applies to all future edits.
- **Never use the semicolon (";") in user-facing copy.** Split into separate sentences, or use a comma, instead. This applies to all future edits.
